        SpeculativeDecodeOptions / DraftProposer / NgramDraftCache /
        DraftModelSession / SpeculationEvent — speculative decoding
        (--spec-type none|ngram-simple|draft-simple), sharing one draft/verify
        loop in GenerationLoop.generate() via the DraftProposer interface
        (propose/observe/close) both drafting strategies implement.
        NgramDraftCache (ngram-simple) indexes n-gram -> next-token from the
        request's own prompt + generated tokens (no second model).
        DraftModelSession (draft-simple, --model-draft PATH) drafts from a
        second, independently-loaded single-shard GGUF pipeline: it drives its
        own persistent KV session (key kvKey+"#draft", distinct from the
        target's) via ordinary greedy forward() calls, then reconciles that
        tentative continuation against ground truth in observe() — walking
        forward from the last agreed position and, on the first mismatch (or
        once it reaches propose()'s own frontier), issuing exactly one
        corrective forward() call so the draft's KV converges without ever
        needing a bulk resend of the whole window. Fail-closed at
        GenerationLoop construction when --spec-type draft-simple is given
        without a loaded draft pipeline, or when the draft and target
        InferencePipeline.vocabSize() values differ (draft-proposed token ids
        are compared directly against the target's own sampled ids, so a
        vocab mismatch would silently compare incompatible id spaces).
        Whichever proposer is active, GenerationLoop.generate() drafts up to
        --spec-ngram-m tokens per round (also draft-simple's max-per-round
        knob) and verifies the whole window in one pipeline.verifyDraft call
        (ForwardPassHandler.forwardVerify: same windowed one-GEMM-per-layer
        path as forwardBatch, but keeps every position's logits instead of
        only the last). Sampling runs exactly once per position in order
        regardless of accept/reject, so rng/grammar state — and the emitted
        token — is byte-identical to --spec-type none; a mismatch emits the
        target model's own prediction and the round ends there (this holds
        for both proposers: the draft's own correctness only ever affects
        acceptance rate, never emitted-token correctness, since `emitted`
        always equals the target's own sampled prediction by construction).
        Wired only for GenerationLoop.generate() (single-request path);
        generateBatch (static multi-request batching) does not draft/verify
        yet — ConsoleMain warns at startup when both --spec-type and a
        --parallel > 1 batch config are set. LlamaTransformerHandler overrides
        forwardVerify (Llama/Mistral/Qwen2 family); Phi2/Phi3/Qwen3/Qwen3-MoE
        and cluster/tensor-parallel pipelines fall back to the
        correctness-preserving serial ForwardPassHandler/InferencePipeline
        default (no speed benefit there yet — named follow-up, see
        docs/infra-plan/PLAN-Infra-Tier9.md). draft-simple is wired for
        ConsoleMain.runLocalRepl() only (loadDraftPipeline() loads a second,
        always-single-shard pipeline sharing the target's MatVec/GpuContext);
        LoRA train/play and cluster/tensor-parallel modes fail closed at CLI
        parse time with an explicit error rather than silently ignoring
        --model-draft (see docs/infra-plan/PLAN-Infra-Tier12.md). The draft
        session is rebuilt fresh on every generate() call, including repeated
        turns of one chat session, so it does not yet share the target's
        cross-turn prefix-cache reuse — a named perf cost, not a correctness
        gap.

  DeviceScratchBudget (node module): sizes the device memory kept free for the
        forward pass when --gpu-layers auto decides how many weight layers to
        upload. Weight upload, the Q4_K dequant scratch and the GPU attention KV
        mirror all allocate from one device, but only the upload was written to
        expect it to run out; filling the card therefore loaded and decoded and
        then failed on the first prompt wide enough to take the batched path.
        The reserve is the widest matmul in the model (hidden x max(hidden, kv,
        ffn) halves) plus a margin, plus the KV mirror at its initial capacity
        when --gpu-attention is active. LlamaTransformerHandler learns the
        per-layer cost by measuring free VRAM across the first upload and stops
        while the reserve is still intact. Every device allocation on the
        inference path falls back to its CPU equivalent on VRAM exhaustion
        instead of propagating: the batched matmul to the weight-stationary CPU
        path, the KV mirror and the attention kernel to CPU attention (the CPU
        KV tensors are always written, so the mirror can be dropped without
        losing history). The attention fallback is taken at the dispatch
        boundary rather than per allocation, so scratch allocated inside the
        kernel is covered too.
  DeviceKvCache written-prefix watermark (node module): dropping the mirror is
        only safe while nothing can read an unwritten position out of it. Device
        memory is never zeroed, so an unwritten row holds whatever the allocator
        last left there and is indistinguishable on-device from a real K/V row;
        attention over it yields noise logits while token counts, timings and
        exit status all still look healthy. DeviceKvCache therefore tracks
        validTokens, the contiguous run of positions actually appended, and
        exposes readableThrough(seqLen) / live(). LlamaTransformerHandler checks
        both before every attention dispatch and before every append, and a
        mirror that runs out of memory is retired by closing it in place --
        never by unmapping it from kvCacheDev, because computeIfAbsent would
        then hand the next token a freshly allocated empty mirror in its stead.
        Retirement is per mirror (per request, per layer), so one layer giving
        up does not cost the others. A request whose prefix was restored into
        the host KV tensors by NodeKVCacheAdapter has no matching device rows,
        and the same watermark keeps it on CPU attention rather than reading the
        restored range out of uninitialized memory.

  metrics — MetricsMain, JfrMetricsExtractor, JdkEventBucket, JfrPercentiles,
        JfrModelMapper, MetricsWriter, MetricsSnapshot, ModelsConfig(Loader).
        Reads .jfr files and writes target/metrics/metrics.json.
        JfrMetricsExtractor accounts for the juno.* events; JdkEventBucket takes
        the JVM events in the same pass — GC pauses (count/max_ms/total_ms),
        allocated bytes, hot methods and lock/park time — so a throughput number
        can be read against the pauses and allocation that produced it. Its
        ThreadAllocationStatistics figure sums each thread's own running total
        rather than every sample, since the field is cumulative per thread. The
        two attribution histograms (top_sites, top_methods) are bounded to ten
        entries and are for reading, not for gating.
        Recording settings: scripts/performance-tests/juno-perf.jfc is the single
        configuration every Juno recording uses, resolved by JunoJfrSettings
        (juno-player) for the in-process recordings and named directly by the

        packaged into the juno-player jar so a jar-launched run resolves the same
        settings; an unresolved file falls back to the JDK stock settings with a

Architecture dispatch (node module): ForwardPassHandlerLoader reads general.architecture.
  phi2, phi3, qwen3 and qwen3moe have dedicated handlers. llama, mistral, tinyllama, qwen2
  and qwen2.5 run on LlamaTransformerHandler; LlamaFamilyArchitectures is that allowlist.
  Any other value (for example gemma4, qwen35, mistral3, minimax-m2) is rejected at load with
  an IOException that names the architecture, instead of falling through to a handler whose
  tensor layout and computation it does not match. In cluster mode a node whose real-model
  load fails (unsupported architecture, unsupported quantization, missing tensor, missing
  file) answers LoadShard with success=false and its reason, then refuses forward passes
  (UnloadedShardHandler); it never falls back to stub output. ProcessPipelineClient and
  TensorParallelPipelineClient fail loadShards() on any node that reports failure, and
  ClusterHarness.start() stops the forked node JVMs before rethrowing. Only a node started
  without a model path (stub mode, used by tests) serves fixed stub output.

Membership: fixed at cluster launch. ModelRegistry is in-memory (two ConcurrentHashMaps).
  There is no dynamic-membership or distributed-registry service: an earlier design for a
  Hazelcast-backed RegistryService and Hazelcast leader election was never built and has
  been removed (the proto RPCs and the dependency).

Prefix cache and KV ownership: prefix reuse is session-scoped. A PrefixCache trie entry names
  KV that must still exist in the pipeline when the entry is hit, so it is written only for
  session requests (whose KV is kept under the session id). GenerationLoop.generate() and
  ContinuousBatchEngine act on a trie hit only for requests that carry a session id.
  GenerationLoop.generateBatch() (static multi-request batching) keys each request's KV by
  its own request id and evicts it on completion, so it never reads or writes the trie and
  prefills every prompt in full.

Tensor parallelism (current state): the gRPC transport, the coordinator-side star AllReduce
  (TensorParallelPipelineClient: broadcast the tokens to every node, element-wise sum of the
  returned float arrays), the shard-assignment data model (TensorShardAssignment) and the
  geometry record TensorShardContext (heads and feed-forward slice width per rank) are built
  and tested. Per-layer weight slicing is not built: no transformer handler reads
  TensorShardContext and the rank a node is given is not used to slice weights, so every node
  loads and runs the full model and returns a complete logit vector. The coordinator then sums
  N complete vectors: N times the memory and compute of a single node, no speedup, and summed
  logits that are N times a single node's (greedy argmax is unchanged; sampling is sharper).
  TensorParallelClusterIT exercises the transport and AllReduce with a fixed-logit stub
  handler rather than a real model. Real column-/row-parallel slicing of the attention and
  feed-forward projections with a per-layer AllReduce is planned for a future
  tensor-parallelism milestone.

Fault tolerance (current state): FaultTolerantPipeline (per-node circuit breakers plus a retry
  policy over replica InferencePipelines) and HealthReactor (health events force-open or
  reset circuits) are built and unit-tested, but nothing in production constructs either.
  CoordinatorMain and ConsoleMain build ProcessPipelineClient / TensorParallelPipelineClient
  directly with no retry or circuit-breaker layer. Pipeline- and tensor-parallel nodes each
  hold a unique, non-interchangeable shard, so the replica-routing model does not apply to
  them as it stands: a lost node in `./juno cluster` currently fails the request with no
  failover. Failure handling for sharded topologies is planned for a future cluster milestone.

GPU FFI (node module — Panama project, JEP 454):
  GpuBindings — vendor-neutral interface implemented by CudaBindings and RocmBindings.
        All accessor methods use vendor-neutral names: gpuGetDeviceCount, gpuGetDeviceProperties,
        gpuSetDevice, gpuMalloc, gpuFree, gpuMallocHost, gpuFreeHost, gpuMemcpy, gpuMemcpyAsync,
        gpuStreamCreateWithFlags, gpuStreamSynchronize, gpuStreamDestroy, blasCreate, blasDestroy,
        blasSetStream, blasSetPointerMode, blasSgemv, blasHSSgemvStridedBatched.
        Each implementation documents the underlying vendor symbol it resolves.
        createMatVec(GpuContext) factory method returns the correct MatVec per backend,
        keeping GpuContext.createMatVec() free of instanceof checks.
        hostMalloc(deviceIndex, bytes)/hostFree(ptr) — pinned host-staging memory
        (cudaMallocHost/hipHostMalloc + matching free); memGetInfo(deviceIndex) — live
        {free, total} device bytes (cudaMemGetInfo/hipMemGetInfo), advisory sizing only.
  CudaBindings — Panama FFI downcall handles for libcudart.so.12 and libcublas.so.12.
        Implements GpuBindings. Singleton; thread-safe; zero per-call Java overhead.
        Requires JVM flag: --enable-native-access=ALL-UNNAMED.
  RocmBindings — Panama FFI downcall handles for libamdhip64.so and librocblas.so.
        Implements GpuBindings. Pre-binds hipHostMalloc flags=0 via MethodHandles.insertArguments.
        opTranspose()=112 (rocblas_operation_transpose). hipDeviceProp_t: sizeof=1472, name@0,
        totalGlobalMem@288 (ROCm 7.2.x, Linux x86_64).
  CudaAvailability — detection via CudaBindings.isAvailable(); zero heap allocation.
  RocmAvailability — detection via RocmBindings.isAvailable(); mirrors CudaAvailability.
  GpuMatVec — sealed interface (permits CudaMatVec, RocmMatVec) extending MatVec.
        Exposes upload / uploadHalf / uploadQ4K; supportsQ4KMmq() for fused path.
        Transformer handlers depend on GpuMatVec, not a concrete vendor class.
  GpuLayerOffload — policy for --gpu-layers / JUNO_GPU_LAYERS (all|auto|0|N).
        Handlers upload only resident global layers; matVec falls back to CPU quant when dev is null.
  MmqOptions — policy for --mmq / JUNO_MMQ (on|off|auto). Default off.
        Ships as VRAM-fit packed Q4 residency; not a decode-speed claim vs FP16-resident.
  GpuAttentionOptions — policy for --gpu-attention / JUNO_GPU_ATTENTION (on|off|auto). Default off.
        CUDA only; measured decode/prefill throughput lever, not a peer-latency claim.
  GqaMath — attention math (QK^T + softmax + weighted-V-sum) extracted from
        LlamaTransformerHandler.gqaInto/gqa; scalar CPU oracle used by both the fallback path
        and the GPU kernel's parity test.
  DeviceKvCache — device-resident FP16 KV mirror kept alongside the host SessionKvTensor
        (dual-write); grow-and-preserve via D2D copy; lifecycle tied to
        LlamaTransformerHandler.evict(). CUDA only.
  GqaAttentionKernel — PTX loader/launcher (CUDA Driver API) for gqa_attention.ptx; one block
        per (batch-row, head), 3-pass QK^T+max / softmax / weighted-V-sum.
  CudaGqaAttention — handler-facing attendBatched(...); real dispatch against DeviceKvCache,
        grow-and-keep-max scratch; one batched launch serves prefill window, single decode, or
        --parallel multi-decode. tryCreate(...) returns null on non-CUDA backends (falls back
        to GqaMath scalar CPU, never silent).
  RmsNormKernel — PTX loader/launcher (CUDA Driver API) for rms_norm.ptx; one block per batch
        row, block-wide sum-of-squares reduction then normalize+scale (Tier 19 Phase A).
  CudaRmsNorm — handler-facing normalizeBatch(...); grow-on-demand device scratch, mirrors
        CudaGqaAttention's shape. Built and parity-tested but deliberately NOT constructed by
        LlamaTransformerHandler — a live A/B found the per-call H2D/kernel/D2H round trip costs
        ~11x more than the scalar CPU rmsNorm it would replace (no device-resident activation
        path exists yet to avoid the round trip). Kept as verified, dormant infrastructure; see
        docs/infra-plan/PLAN-Infra-Tier19.md "Measured finding".
  CudaGraphSession — generic CUDA driver graph capture/replay wrapper (cuStreamBeginCapture /
        cuStreamEndCapture / cuGraphInstantiate / cuGraphLaunch); captures a fixed async op
        sequence once, replays it against fresh data in the same fixed buffers. Tested against
        RmsNormKernel's launch sequence: cut ad-hoc per-call overhead ~3.2x but still left it
        slower than CPU for a single isolated op (the sync-point cost only amortizes across a
        chain of graphed ops). Not wired into any handler; see PLAN-Infra-Tier19.md.
  LoraMmqPolicy — playback-only MMQ gate (juno.lora.play.path); train stays FP residency.
  LoraResidentUpload.runPlayback — play Q4 OOM closes packed buffers and falls to CPU
        without the train FP16 microbatch retry.
  ResidentQ4KWeight — LoRA play wrapper around DeviceQ4KMatrix (forward-only).
        (classpath q4k_gemv.ptx); JFR backend cuda-resident-q4k.
  ResidentQ4KWeight — LoRA play wrapper around DeviceQ4KMatrix (forward-only).
  CudaMatVec — implements GpuMatVec; cublasSgemv_v2 (FP32) / cublasHSSgemvStridedBatched (FP16)
        / fused Q4_K GEMV when --mmq; per-thread CUDA stream + async H2D/D2H;
        sgemvSameX uploads shared activations once for Q/K/V and gate/up groups.
  RocmMatVec — implements GpuMatVec; rocblas_sgemv (FP32) / rocblas_hssgemv_strided_batched (FP16);
        same three compute paths as CudaMatVec; per-thread HIP stream; sgemvSameX mirror.
  DeviceFloatMatrix / DeviceHalfMatrix / DeviceQ4KMatrix — VRAM buffer wrappers using GpuBindings
        deviceMalloc / deviceFree; explicit lifecycle via releaseGpuResources().
        Vendor-neutral half/float; Q4_K path is CUDA-only.
  GpuContext — shared BLAS handle + serialization lock per device index.
        selectBindings() auto-detects: CUDA first, then ROCm.
        Override: -Djuno.gpu.backend=cuda|rocm|auto.
        createMatVec() delegates to GpuBindings.createMatVec(GpuContext) — no instanceof checks.
        freeVramBytes() — live free-VRAM query (GpuBindings.memGetInfo), used by coordinator's
        PrefillBatchOptions.resolveAdaptive for whole-prompt prefill chunk sizing on static schedule.

vision — Image-to-text (I2T) module. GGUF-based CLIP ViT encoder, patch
        embedder (javax.imageio; no new deps), and ForwardPassHandler decorator.
        depends on: node, coordinator, registry, tokenizer, sampler.
        depended on by: juno-player, juno-master.
        node does NOT depend on vision — no cycle is possible.
 
  VisionConfig   — reads clip.* / vision.* GGUF metadata keys; derives
                   numPatches, numVisionTokens, headDim.
  VisionModelPaths — resolves which GGUF file to probe/load CLIP vision
                   tensors from: the separate mmproj file when one is given,
                   else the base model file (merged-file or embedded fallback).
                   Pure logic, no I/O; unit-tested directly without a GGUF fixture.
  ImagePatchEmbedder — decode → bilinear resize → CLIP normalise → CHW float[].
  VisionEncoder  — pure Java CLIP ViT forward pass (patch embed, CLS, positional
                   embed, pre-LN, N transformer blocks, vision projector).
                   Reads v.patch_embd.weight, v.blk.{i}.*, mm.0.weight from GGUF.
                   MatVec-pluggable (CPU or GPU). Thread-safe (read-only weights).
                   Per-block FFN loading (loadFfn/resolveFfnOrientation) does NOT
                   trust the ffn_up/ffn_down tensor names to indicate direction —
                   some mmproj exports (e.g. llava-phi-3-mini) have them reversed.
                   Direction is instead read from each tensor's own GgufReader.
                   tensorDims() output dimension; a mismatch on both orientations
                   throws IllegalStateException at load time instead of an opaque
                   ArrayIndexOutOfBoundsException mid-request. Likewise
                   outputDim()/resolveProjectorOutputDim() does NOT trust
                   clip.vision.projection_dim metadata for the projector's real
                   output width — some files (same llava-phi-3-mini) declare a
                   value there that doesn't match mm.0.weight's own GGUF shape.
                   Every caller needing the true patch-vector width (project(),
                   LlavaHandlerFactory's VisionAwareForwardPassHandler sizing)
                   uses outputDim(), never config().projectionDim().
  VisionAwareForwardPassHandler — ForwardPassHandler decorator. On the first node
                   (hasEmbeddings=true), replaces IMAGE_TOKEN_ID embedding lookups
                   with pre-computed patch vectors from ConcurrentHashMap[requestId],
                   then delegates to the wrapped LlamaTransformerHandler via a
                   withActivations(...) request (tokenIds=null). The wrapped
                   handler's forward()/forwardBatch()/forwardMultiDecode() decide token-lookup vs.
                   activations by request.isFirstNode() (tokenIds != null), NOT
                   by hasEmbeddings alone — hasEmbeddings only means this node
                   is capable of a lookup, not that this specific request wants
                   one (2026-07-12 fix: the old hasEmbeddings-only check NPE'd
                   on tokenIds()[b] whenever a request carried activations here).
                   Delegates all other tokens and all subsequent nodes to the wrapped
                   LlamaTransformerHandler unchanged.
  LlamafileGgufIndex — scans a llamafile ZIP for ALL embedded GGUF entries,
                   not just the first. Returns List<Entry> (name, dataOffset).
                   Lives in the node package so it can access the package-private
                   GgufReader.GGUF_MAGIC and GgufReader.readZip64ExtraLocalOffset.
                   Used by LlavaHandlerFactory to locate an embedded vision encoder
                   (e.g. moondream2's SigLIP GGUF) without a separate --mmproj-path.
                   Implements its own EOCD+CD walk; does not fall back to the
                   forward-scan path (findGgufOffsetByForwardScan) since all known
                   multi-GGUF llamafiles use accessible ZIP64 EOCD. Plain .gguf
                   files and non-ZIP files return an empty list.
  GgufReader — added openAtDataOffset(Path, long) factory: opens a GGUF at an
                   explicit byte offset within a llamafile, bypassing the ZIP scan.
                   Internal open() body extracted to parseGgufFromChannel(channel,
                   offset) so both open() and openAtDataOffset() share the same
                   header/metadata/tensor-table parsing path. GGUF_MAGIC and
                   readZip64ExtraLocalOffset are now package-private (were private)
                   so LlamafileGgufIndex can reuse them without duplication.
  LlavaHandlerFactory — the ONLY place that knows "this is a LLaVA/vision model".
                   Lives in vision (not in node) to keep the dependency direction
                   correct. isVisionArchitecture(modelPath, mmprojPath) and
                   buildFromHandlers(modelPath, mmprojPath, handlers, config) both
                   resolve the vision-weights file via VisionModelPaths before
                   opening a GgufReader. Two-step detection: (1) open the primary
                   visionWeightsPath and check for v.patch_embd.weight; (2) when
                   no separate mmproj was given, call LlamafileGgufIndex.scanAll()
                   and probe each additional GGUF entry for v.patch_embd.weight
                   (the moondream2 embedded-GGUF path). resolveVisionReader() and
                   findEmbeddedVisionEntry() are private helpers that centralise
                   this logic for both isVisionArchitecture and buildFromHandlers.
                   Wraps handlers.get(0) in VisionAwareForwardPassHandler. Returns
                   Built record with all wired components for ConsoleMain to consume.
  VisionInferenceRequest — immutable record; carries imageBytes alongside messages.
  VisionChatHandler — Javalin handler for POST /v1/vision/chat (blocking) and
                   POST /v1/vision/chat/stream (SSE). Reads multipart/form-data
                   (image part + request JSON part). Encodes image, registers
                   patches, submits InferenceRequest, releases patches in finally.

  generic extension point used to attach the vision routes; there is no
  vision-specific method on this class.
 
ConsoleMain (juno-player module) — runLocalRepl() (--local mode only) calls
  prepareVisionHandler() BEFORE LocalInferencePipeline.from(), which calls
  LlavaHandlerFactory.isVisionArchitecture()/buildFromHandlers() and, if the
  resolved vision-weights file has v.patch_embd.weight, wraps handlers.get(0)
  in place with VisionAwareForwardPassHandler. This ordering is load-bearing:
  LocalInferencePipeline.from() snapshots each handler reference into its
  NodeStage list at construction time and never re-reads the handlers list
  afterwards, so the wrap MUST land before that call or the pipeline silently
  keeps using the unwrapped text handler forever (2026-07-12 bug: this used to
  be called wireVisionRoutes() and ran after pipeline construction — see
  CHANGELOG). Once apiServer exists, registerVisionRoutes() separately
  registers /v1/vision/chat and /v1/vision/chat/stream via
  InferenceApiServer.addRoutes() using the already-built Built record.
  --mmproj-path PATH is the CLI flag carrying the separate mmproj file through
  to prepareVisionHandler(); without it, isVisionArchitecture() probes
  --model-path itself and returns false for every real (two-file) I2T model.
  KNOWN LIMITATION: runClusterRepl() (--cluster mode) does not call
  prepareVisionHandler() — vision routes are --local mode only.
 
ModelIdResolver (registry module, cab.ml.juno.registry) — shared by
  VisionChatHandler (juno-player), OpenAiChatHandler and InferenceApiServer
  (coordinator): resolves a client-supplied "model" field against
  ModelRegistry with one rule all three previously implemented separately
  (and inconsistently): blank/absent -> the loaded model; exact match ->
  that model; mismatch -> error listing loaded ids, UNLESS the caller opted
  into FallbackPolicy.SINGLE_MODEL_FALLBACK and exactly one model is loaded,
  in which case it falls back to that model and logs a WARNING (was a hard
  503 before, for every caller, regardless of how many models were loaded).
  VisionChatHandler and OpenAiChatHandler opt into SINGLE_MODEL_FALLBACK
  (the user-facing REST surfaces where a copy-pasted/wrong model name is
  common); InferenceApiServer's native /v1/inference API keeps
  FallbackPolicy.STRICT (the resolve(registry, requested) 2-arg overload's
  default) — pinned by InferenceApiServerTest, which expects an explicitly
  wrong model id to always 503 even with one model loaded. Pure logic over
  ModelRegistry's public API, no I/O — unit-tested directly
  (ModelIdResolverTest, covers both policies).

OpenAiChatHandler / SamplingParams — OpenAI chat fields stop, seed, and
  presence_penalty map into SamplingParams and the decode loop
  (StopSequenceFilter + PresencePenaltyStep + seeded Random). response_format
  type=text (or absent) is unconstrained; json_object / json_schema compile to
  GBNF and mask illegal tokens before sample (GrammarSession). x_juno_grammar
  is raw GBNF and conflicts with json_* types. Unsupported schema keywords
  fail closed. logit_bias and user remain ignored with docs honesty.
  CLI --grammar-file / --json-schema-file (JUNO_GRAMMAR_FILE /
  JUNO_JSON_SCHEMA_FILE) attach the same SamplingParams.grammar on local and
  cluster inference; LoRA /train is an explicit no-op.

OpenAiTools / ToolPrompt / ToolCallParser — OpenAI tools and tool_choice on
  chat completions. ToolPrompt injects schemas for llama3, chatml, and qwen3
  templates and fails closed on other families. ToolCallParser reads
  <tool_call> blocks (and raw JSON) into message.tool_calls. tool_choice=none
  skips inject/parse. required / named choice compiles a GBNF envelope via
  ToolCallGrammar + JsonSchemaToGbnf. tools conflict with json_* /
  x_juno_grammar / CLI grammar (HTTP 400). /v1/vision/chat does not honor tools.

MiniJinjaTemplate / EmbeddedChatTemplate / GgufChatTemplateResolver /
  EmbeddedChatTemplateRegistry (tokenizer module) — GGUF-embedded chat
  template support. MiniJinjaTemplate is a restricted Jinja-subset engine
  (package-private): {{ output }}, {% for x in messages %}, {% if/elif/else %},
  string concat, ==/!=/</<=/>/>=, and/or/not, trim/upper/lower filters,
  {%-/-%} whitespace trim, loop.index0/index/first/last/length. Unsupported
  syntax (set, macros, filter args, non-literal bracket indices, non-list
  for-targets) throws MiniJinjaException at parse or render time — never a
  raw/uncaught exception. GgufChatTemplateResolver.resolve(GgufReader,
  fallbackModelType) reads tokenizer.chat_template metadata, parses it, and
  smoke-renders a probe conversation before committing to it; any failure at
  any stage falls back to the existing ChatTemplate.forModelType(fallback)
  path unchanged. EmbeddedChatTemplate wraps a validated MiniJinjaTemplate +
  fallback ChatTemplate; format() also catches per-call render failures and
  falls back, so a template that only breaks on some real message shapes
  degrades to the named template rather than crashing generation.
  EmbeddedChatTemplateRegistry is a process-local String->ChatTemplate map;
  ChatTemplateFormatter.forModelType(modelType) checks it before the named
  lookup — this is how a template resolved once at model load reaches every
  GenerationLoop / ContinuousBatchEngine / JunoPlayer call site that already
  calls forModelType(req.modelId()), with no change to those call sites.
  Nothing populates the registry automatically: ConsoleMain.
  registerEmbeddedChatTemplate(modelPath) (juno-player) is the only writer,
  called from runLocalRepl() and runClusterRepl() (registers under both the
  ChatModelType short key used by the REPL and the raw GGUF filename used as
  the REST/OpenAI model id — see buildLocalModelRegistry) — deliberately not
  called from runLoraRepl(), so juno lora train / --lora-play keep using the
  named template only (train/inference formatting must stay identical for
  adapter recall); LoraTrainNotices.EMBEDDED_CHAT_TEMPLATE_IGNORED (node
  module) surfaces that as a startup notice when the loaded GGUF has one.

HfGgufFetcher (juno-player module) — resolves a Hugging Face Hub
  "org/repo[:quant]" spec (--hf CLI flag, wired in ConsoleMain.main() ahead of
  the --model-path null check, and in scripts/run.sh / run.bat for cluster,
  local, and lora) to a local GGUF path. listGgufAssets() calls the Hub
  models API (GET /api/models/{repo}, "siblings[].rfilename" filtered to
  *.gguf); selectAsset() prefers a filename containing the requested
  ":quant", else PREFERRED_QUANT ("Q4_K_M"), else the alphabetically-first
  .gguf asset. download() does a HEAD for the remote ETag (cache hit skips
  the body download when it matches a ".etag" sidecar next to the cached
  file), and resumes a partial ".part" file via an HTTP Range request when
  present. Cache root is ~/.cache/juno/models/<org>_<repo>/ by default
  (constructor-overridable for tests) — never models/, which CLAUDE.md
  reserves for manually placed local fixtures. Plain java.net.http.HttpClient
  + the existing Jackson dependency; no new Maven dependency, no Python.
  Tested against com.sun.net.httpserver.HttpServer (HfGgufFetcherTest) — no
  real network access in tests. ConsoleMain.resolveHfSpecOrExit() resolves
  --hf into the effective --model-path; when both flags are given and
  disagree (different resolved file), it fails fast with an error rather than
  silently preferring one.

Embeddings API (Infra Tier 11) — POST /v1/embeddings (coordinator module), off by
  default. InferencePipeline.embedTokens(requestId, tokens) (node module) is a
  default method that throws UnsupportedOperationException — a fail-closed
  contract satisfied only by LocalInferencePipeline; gRPC / tensor-parallel /
  pipeline-parallel pipeline implementations (ProcessPipelineClient,
  TensorParallelPipelineClient, StubInferencePipeline in tests) inherit the
  default and therefore fail closed, matching --schedule continuous's
  local/single-shard-only scope. LocalInferencePipeline.embedTokens runs the
  same causal-prefill loop embedLastToken always ran (one forward pass per
  prompt position through every pipeline stage), but now keeps every
  position's ForwardPassHandler.lastRmsHiddenForEmbedding result instead of
  overwriting all but the last — no extra compute, just no longer discarding
  work already being done. embedLastToken(requestId, promptTokens) is now a
  thin wrapper returning embedTokens(...)[last]; both now call evict(requestId)
  before returning, fixing a pre-existing per-request KV-cache leak (embedding
  extraction is one-shot with no follow-up decode, so nothing else ever
  evicted that state). EmbeddingPooling.pool(hidden, PoolingMode) (node
  module) reduces the per-position hidden matrix to one vector: MEAN
  (default), CLS (first position), LAST (final position — logs a one-time
  quality warning in EmbeddingsHandler, since it under-represents chat-tuned
  prompts). EmbeddingsHandler (coordinator module) bypasses RequestScheduler /
  GenerationLoop's sampler-driven decode loop entirely — it runs directly on
  the Javalin request's own virtual thread, so v1 embeddings requests do not
  share the chat completions queue-depth limit or 429 semantics. CLI
  --embeddings (enables the route; RequestScheduler.generationLoop() is a new
  package-private accessor EmbeddingsHandler uses to reach the tokenizer and
  pipeline) and --pooling mean|cls|last thread through both ConsoleMain
  runLocalRepl() and runClusterRepl() and scripts/run.sh / run.bat for local
  and cluster; cluster mode accepts both flags (no per-mode branching needed
  in scripts) but prints a startup warning that every request will 400,
  since its pipeline never implements embedTokens.
