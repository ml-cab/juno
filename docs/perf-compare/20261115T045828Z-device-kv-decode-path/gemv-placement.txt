# FFN gate and up GEMVs (Q4_K 11,008 x 2,048) on Qwen2.5-3B: what moves them. Scratch builds of this tree (experiments, not published code),
# each JVM traced as above; ratio = the two launches' per-layer median time, run over reference, min and max over the 36 layers.

## The quantized kernels themselves (an FP16 JVM also running them on a shadow q8_0 cache, right after its own attention; reference: the same build without)
encoder only:            min 0.990 max 0.993
attention only:          min 0.990 max 0.992
encoder and attention:   min 0.990 max 0.993

## Weight placement (an FP16 JVM that loads the quantized attention module before its weight upload, as a q8_0 JVM does)
FP16 + module first over FP16: min 0.994 max 0.997

## Allocation sizes (reference: FP16 JVM of the scratch build)
q8_0, mirrors as allocated: min 1.039 max 1.042
q8_0, mirrors allocated at FP16 size: min 0.989 max 0.992

## The region's buffers (q8_0 JVM, one buffer moved to a 64 KiB boundary)
q8_1 input vector at a 64 KiB boundary: min 1.009 max 1.013
tail scratch (GEMV output) at a 64 KiB boundary: min 1.068 max 1.072
